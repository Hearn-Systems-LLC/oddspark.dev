Add a regression where assembly notice binding changes the provider Candidate ref. This is spike-only and does **not** change assembly bytes.

## Accepted strike followed by pipeline failure

The assembly did proceed beyond `strike.code === accepted`. It selected `strike.source.kind === candidate`, built the committed artifact, and called the coordinator commit port. The failure is the spike coordinator's receipt shape:

- `worker.mjs:35-37` returns `committed_at` as an ISO string.
- `assembly.mjs:169-174` accepts a commit only when `parseReceipt` validates it.
- `receipts.mjs:140-143` requires `committed_at` to be a nonnegative safe integer. The ISO string is rejected, so assembly throws its fail-closed writer error.
- The writer catch re-reads the same malformed receipt, cannot validate it, releases the held claim best-effort, and rethrows. Commit never becomes authoritative and render is never reached.

Minimal functional fix: change the spike coordinator receipt to `committed_at: now()` and add a test that round-trips the fake receipt through the production receipt parser before claiming commit success. This is spike-only and does **not** change assembly bytes. Minimal observability fix: retain the caught error class and a bounded failure stage, and preserve the already-known strike source classification while still reporting `pipeline_failed`; this also does not change assembly bytes.
