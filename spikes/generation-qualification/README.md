# Generation structural qualification

This offline-first harness qualifies the frozen primary and fallback generation identities independently. It accepts only a direct closed Story 1.7 Candidate. Text, Markdown fences, wrappers, coercion, extraction, repair, and replacement are hard failures and remain in the originating role's denominator. Per the 2026-08-22 governance amendment, a scheduled call (probe or trial) may retry only when its attempt ends in a transient call state (`provider_error` or `timeout`) — never after an output classification — at most once per scheduled call; every attempt is retained in evidence with its attempt index, and a trial counts once under its final attempt's classification.

Run `npm run spike:generation:self-test`, then generate a reviewable plan with `npm run spike:generation:plan -- <plan-id>`. The command creates a fresh OS-temporary directory outside operational results containing exactly the plan, a null approval template, and a null execution marker with `allowance_consumed:false`. Planning and verification make no network or inference calls. The public verifier accepts arbitrary evidence bytes with `npm run spike:generation:verify -- --file <evidence.json>`.

Live execution is deliberately separate from `npm run check`. An operator must review the exact plan, confirm provider/account/headroom/pricing/retention, and create a fresh closed approval record with schema `oddspark.generation-qualification-approval/v2`, the exact `plan_ref`, `approval_run_id`, `approved_at`, nonblank `approved_by`, call cap `63`, exact `approved_maximum_usd`, and authorization `execute-exact-plan-once`. Starting the isolated adapter requires `npm run spike:generation:dev -- <exact-plan.json> <exact-approval.json>`; the launcher independently validates both files, refuses a consumed/cross-plan cycle, and terminates the adapter when approval expires. The primary is the selected Llama 70B fast endpoint and fallback is the selected gpt-oss-20b endpoint; retained gpt-oss r2/r3 bytes are legacy NO-GO history and grant no current authority.

The runner refuses CI/non-TTY execution, non-loopback or credential-bearing URLs, stale/mismatched approval, adapter/source/runtime drift, and an existing spend receipt before inference. It reserves the immutable receipt before the first call, runs one probe then 20 sequential trials per role only after that role's probe succeeds, retries a scheduled call once only after a transient `provider_error`/`timeout` attempt, makes at most 63 calls (42 scheduled + up to 21 retries), and publishes marker-bound evidence atomically. If the cap is exhausted mid-schedule the run stops and remaining trials stay absent, so verification fails closed on cardinality. A NO-GO role requires architecture review; it never changes the other role's decision. Credentials, account IDs, and provider reasoning are not retained.
