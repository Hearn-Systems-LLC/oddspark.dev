# Addendum — Oddspark Opportunity Brief PRD

Technical-how and mechanism detail preserved for architecture/solution design. Not normative PRD content.

## Current implementation mechanics (src/worker.js, to be revisited by architecture)

- **Seed scheme:** drand League of Entropy quicknet (3s rounds) + NOAA SWPC GOES X-ray flux (1min). Floored to every 100th round (~5-minute window) so same-window visitors get the identical spark.
- **Caching:** results cached in KV under a seed-derived id; reproducible and third-party verifiable ("randomness with a receipt" — the site's central joke).
- **Legacy generation:** four independent random axes — DOMAINS (who), lens (why), form (what), friction (sting) — selected from fixed lists. This composition strategy is what the pipeline replaces.
- **Existing site scan (domain mode):** budget `SCAN_BUDGET_MS=4000`, `SCAN_BYTE_LIMIT=512KB`, `SCAN_PAGE_LIMIT=3`, `REDIRECT_LIMIT=3`, `WEBSITE_LENGTH_LIMIT=2048`, request body limit 4096. Degradation warnings already exist: UNAVAILABLE / LIMITED / CLARITY.
- **Rate limiting / abuse:** visitor window 1h, domain limit 10 per visitor, spark-id regex, claim lease 20s, profile TTL 24h. The separately governed domain-result TTL is exactly 1h from authoritative commit (Justin decision, 2026-08-17).
- **Local permalink retention:** local public `/s/:id` artifacts and their authoritative receipts expire exactly 30 days after commit (Justin decision, 2026-08-17). Domain-scoped artifacts remain governed by the separate one-hour/no-permalink rule.

## Deferred decisions parked during PRD drafting

- **Historical OQ1 — resolved by AD-7:** cache-first commit preserves committed-artifact reproducibility without claiming model determinism. Earlier options included seed-as-generation-input, seed-as-candidate-selection, or retiring the receipt; they are retained here only as decision history.
- **Gate shape settled; qualification deferred (Open Question 3):** local deterministic/policy validation precedes a separate one-call semantic judge, and the inner canonical verdict remains `{pass,gates[9],tone,claims}`. Architecture must still qualify the exact judge provider/model, candidate-bound outer wire representation, lossless canonical adapter, primary/fallback configurations, and latency allocation.
- **Provider metering mechanism:** every role shares the six-call strike ledger and hard deadline while using its role-qualified selector. Workers AI retains `NeuronMeter`; another provider requires an approved equivalent cost meter and budget before qualification.
- **Historical OQ4 — resolved by AD-8:** measurement uses server-side aggregate `briefs_served`, `house_briefs_served`, and `invitation_acted` counters atomically owned by COORD, KV report snapshots, and `POST /api/cheer`; failed 400/502 responses enter no served-outcome denominator, and no per-visitor tracking is added beyond the declared abuse carve-out. The resulting invitation metric is an approximate event rate, not a deduplicated person/render percentage.
- **Launch fallback gate — owner decision 2026-08-17:** after at least 100 authoritative production `briefs_served` events, public launch requires `house_briefs_served * 100 < briefs_served * 10` (strictly below 10%). This is a served-event ratio, not a unique-visitor or model-failure percentage. The launch report separately requires complete same-interval platform HTTP outcome coverage; unexplained 5xx or incomplete coverage blocks overall PASS pending reliability review and is never folded into the house ratio.
- **Activation integrity — pre-mortem decision 2026-08-17:** production consumes one closed canonical activation manifest written atomically as a single deployment value. It binds the deployed source identity and every applicable qualification, full-request, catalog, Hearn receiver, and receipt-claim ref. Partial or individually supplied refs reject. Stronger receipt/reproducibility copy renders only when its exact approved claim-proof ref is current; otherwise the non-claiming copy remains.
- **Stakeholder safeguards — elicitation decision 2026-08-17:** fixed reference-bearing invitation copy states the 30-day local and one-hour domain expiries and never promises later Hearn recovery. Invalid activation configuration disables model/claim/reference features without crashing the shell. Launch availability evidence is interval-based, aggregate, and privacy-safe. Receiver proof is stale after either side's relevant contract/deployment behavior changes. A deterministic on-demand decision view shows every gate without creating new state, while deployment, quiet observation, promotion, claim activation, and destructive retirement retain separate approvals.
- **Subtraction pass — elicitation decision 2026-08-17:** the production activation manifest contains shared generation/judge/semantic refs once, nests only mode-specific Evidence/full-request state, is the sole deployed activation value, and has a runtime-derived hash. HTTP evidence uses a frozen interval rather than invented cumulative starting totals. Diagnostics use existing observability and create no new storage.
- **Invitation destination — owner decision 2026-08-17:** with an exact matching active closed `HearnReceiverManifest`, an accepted `POST /api/cheer` returns a fixed `303` to `https://hearn.systems/contact?source=oddspark&spark=<encoded-id>`. Only the opaque artifact id crosses origins, and it is resolvable only during the artifact's approved lifetime. The Hearn contact form must preserve it in the submitted conversation record; that repository change requires separate approval. Without a current receiver ref, Oddspark renders the plain fixed contact link, sends no reference, and records no invitation event. SM-1 reports disclose receiver-activation coverage. Domain Brief content remains governed by Oddspark's one-hour read boundary.
- **Owner review — readiness remediation 2026-08-17:** the first SM-2 / SM-3 review cycle is Story 3.3 after Story 3.2 `LOCAL PASS`. It does not wait for Story 2.10, Story 3.4 `DOMAIN PASS`, or organic volume. Weekly review after that follows `owner-review-runbook.md` and is not a sprint story.
