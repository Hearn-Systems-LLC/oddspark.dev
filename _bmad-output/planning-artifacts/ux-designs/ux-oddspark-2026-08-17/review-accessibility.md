# Accessibility Review — oddspark

Reviewed: `EXPERIENCE.md`, `DESIGN.md`, `../../ux-decision-record-oddspark.md` (UX-DR2/3/4/6, D1–D16), against `src/worker.js page()` L1443–1628 (CSS), L1633–1690 (markup), L2100–2150 (strike JS), `howPage()` L2161–2385. Standard applied: WCAG 2.2 AA as the record declares. Contrast ratios below are computed from the exact hex values (sRGB, WCAG relative-luminance formula), not the ≈ estimates in the extract.

## Overall verdict

The three files move the shell from clearly failing (no landmarks, no h1 on idle, `--faint` at 2.05:1, no announcements) to a defensible AA baseline, and the intent is right in almost every place. But three of the concrete decisions would be implemented *wrongly from the wording as written*: the A/B button-label flip is only correct for A and actively breaks B (heading on B = 2.99:1, void on B = 5.37:1); the settle choreography (focus move + a polite live region that contains the whole card + `role="alert"` nested inside it) produces double and triple announcements; and the "adjacent" 400 message with no `aria-describedby` and a `disabled` button that drops keyboard focus mean the error path is not actually operable as specified. Fix those, pin the fixed-gold text roles to a variable that does not track the sun, give the input a visible resting border, and provide a pause for the continuously rotating canvas, and the spec is AA-sound.

## Findings

- **[critical]** The A/B label flip is half wrong. Computed: on `solar-a #4A6785` label `#0B0D10` = **3.31:1 (fail)**, label `#E4EAF0` = **4.85:1 (pass)** — flip correct. On `solar-b #5E8CA8` label `#0B0D10` = **5.37:1 (pass)**, label `#E4EAF0` = **2.99:1 (fail)** — the flip *breaks* a passing pair. The extract's ≈4.1:1 estimate for B was wrong and propagated. (`DESIGN.md § Contrast statement`; `EXPERIENCE.md` A3; record UX-DR2.9, D9.) *Fix:* flip to `{colors.heading}` on **A only**; keep `{colors.void}` on B/C/M/X. Add the actual numbers to the DESIGN.md contrast statement so the test asserts them, and write the axe/contrast fixture for all five accent classes, not one.
- **[critical]** Text roles that DESIGN.md pins to `{colors.solar-c}` are implemented as `var(--solar)` in the shell (`.field dd.hot`, `.legend em`, `.question b`, `.mark span`; JS re-sets `--solar` on settle at L1791). On an A-class day those become `#4A6785` on void = 3.31:1 at 10.5–12.5px — fail. The spec's "hotValueColor: solar-c" only holds if a second CSS variable exists. (`DESIGN.md § components.prov-table / accent-bar / invitation-*`; as-built L1500–1587.) *Fix:* state explicitly that `--solar` (live) is used only for the strike-button fill, the live dot, and the accent bar; every *text* role in solar gold uses a fixed `--gold:#C9A227` (8.04:1). The `.mark span` wordmark may stay live under the logotype exemption. Add "solar-c is a fixed token, not the live accent" to the token table's "Not used for" column.
- **[high]** Settle choreography double-announces. UX-DR3.5/UX-DR2.6 put `aria-live="polite" aria-atomic="false"` on the *result container* and also move focus to the `h1`. Screen readers will (a) announce the focused heading, then (b) queue the polite region's inserted content — which is the entire card, since all eight elements are inserted at once — including notice, title, plan, chips. VoiceOver/NVDA users get the title twice and then a multi-paragraph unstoppable read. Additionally the 502 message is `role="alert"` *inside* the polite region (nested live regions → announced twice), and the "Working…" sentence lives in the same region as the card it is replaced by. (`EXPERIENCE.md § Interaction Primitives 5`, `§ Accessibility Floor → Live regions`; record UX-DR2.6, UX-DR3.7–8, D5.) *Fix — minimal correct pattern:* (1) the result region is **not** a live region; (2) one small dedicated `<p id="status" role="status">` (visually hidden or the existing strike-note slot) carries "Working. Your spark takes a few seconds." on submit and is cleared on settle; (3) on settle, move focus once to `h1[tabindex="-1"]`; if a notice exists, either place it inside the status text ("Ready. No usable pages came back… <title>") or give the `h1` `aria-describedby="notice"` so the notice is read after the title on focus — pick one and state it, because "notice before title" is only achievable via the status sentence, not via focus; (4) 502: text goes into the status element as `role="alert"` (or `role="status"` — polite is enough since focus is also managed) and focus is programmatically returned to the button (see next finding). Drop `aria-busy` from the button.
- **[high]** `disabled` on the button drops keyboard focus. When the focused `<button>` becomes `disabled`, Chromium/Firefox move focus to `<body>`; the spec's 502 row "focus stays on the button" is therefore false as written, and 2.4.3 is broken between submit and settle. `aria-busy` on a `<button>` is also the wrong element — `aria-busy` describes a region whose content is being updated, and most SRs ignore it on a control. (`EXPERIENCE.md § State Patterns → 502`, `§ Interaction Primitives 1`; record UX-DR3.1/3.7, D6.) *Fix:* either use `aria-disabled="true"` + ignore clicks (keeps focus, still announces "dimmed") or keep `disabled` and explicitly `focus()` the button on 502/other non-Brief settles. Put `aria-busy="true"` on the result region during the strike if it is kept at all. Reword UX-DR3.7: "focus moves once to the `h1`; when no Brief renders, focus is set to the strike button (400: to `website-input`)."
- **[high]** 400 error message is "adjacent" but not associated. `aria-invalid="true"` + a nearby `role="alert"` paragraph does not tell the SR user *what* is wrong when they land on the input; 3.3.1 is satisfied by the visible text but 1.3.1/4.1.2 are not, and moving focus to the input while an alert fires produces a race (alert may be cut off by the focus announcement). (`EXPERIENCE.md § website-input`, `§ State Patterns → 400`; record UX-DR4 400 row, D5.) *Fix:* the message element has a stable `id` and the input carries `aria-describedby="website-error"` while invalid; move focus to the input; no `role="alert"` needed on the message (or use `role="alert"` and *don't* move focus — not both). State that the message container exists in the DOM at load (empty) so an alert role fires reliably.
- **[high]** The no-JS form path conflicts with "the 400 response is unchanged" and with `/api/spark` returning JSON. A native `<form method="post" action="/api/spark">` submitted without JS gets a JSON body (or the plain-text 502 at L2529) rendered raw in the browser tab. Also POST-then-refresh re-strikes; POST-redirect-GET to `/s/:id` is impossible for domain/downgrade Briefs which have no permalink. (`EXPERIENCE.md § Interaction Primitives → Progressive enhancement`, A19; record D1, UX-DR4 rule 5, D14.) *Fix:* specify content negotiation: `/api/spark` returns the shell HTML (result rendered, `<title>` = spark title, focus at document start is acceptable, `h1` server-rendered) when the request has `Accept: text/html` or a form content type, JSON otherwise; 400 → 200/400 with the shell and the field message associated to the input; 502 → shell with the message. Note in UX-DR4 that "400 body unchanged" applies to the JSON representation only. Reload after a domain POST re-strikes — say so or return the domain Brief on a one-hour cache-keyed GET.
- **[high]** The idle `website-input` boundary is invisible to low-vision users: border `#1D242C` on `#0B0D10` = **1.24:1**, fill `#101419` vs void = 1.06:1. 1.4.11 requires 3:1 for the visual boundary of a control in its resting state; the entropy border/ring only appears on focus. (`DESIGN.md § components.website-input`, `§ Contrast statement` claims "3:1 for UI borders" but the border token is `rule`.) *Fix:* input resting border → `{colors.dim-raised}` (5.59:1) or at least `{colors.dim}` (4.02:1). Chip borders may stay `rule` (non-interactive) but should not be cited as meeting 3:1.
- **[high]** `{colors.dim}` `#67737F` = **4.02:1** and is the colour of the actual `h2` section headings ("Seed Geometry", "Provenance", the six Brief section labels), the `.live` readout, `.question` text, `.legend b`, `.formula`. DESIGN.md's rationale — "decorative repeats of information also present in the DOM heading" — is wrong: they *are* the DOM headings, 10.5px uppercase, not large text. Fails 1.4.3. (`DESIGN.md § Contrast statement`, `components.section-heading`.) *Fix:* section-heading and `.live` colour → `{colors.dim-raised}` (5.59:1); demote `dim` to non-text (dividers/disabled) alongside `faint`, or reserve it for text ≥18.66px, which never occurs (mono never exceeds 14px).
- **[high]** Continuously rotating canvas has no pause control (2.2.2 Pause, Stop, Hide). rAF rotation and the corona pulse auto-start, last more than 5s, run in parallel with content, and are only stopped by `prefers-reduced-motion`. Honouring the OS setting is not a substitute for a user-operable mechanism, and the preservation criteria (`EXPERIENCE.md § Responsive & Platform` items 10–11) freeze the current behaviour. None of the three files mentions 2.2.2. *Fix:* add one visible text control in the legend row (e.g. "pause" / "resume", `<button>` styled as `footer-link`) that stops the rAF loop and the dot's breathe; drag-to-rotate can stay. Alternatively pause the loop when the stage is not hovered/focused and after the 950ms assemble — but an explicit control is the safe reading. Note this as a delta D17.
- **[medium]** Persistent-`h1` wording will be implemented as node replacement. "Product name … replaced by the Spark title on settle" invites devs to remove one `h1` and insert another, or to make the masthead wordmark an `h1` *and* keep the card `h1` (two `h1`s on the permalink and after settle). Node replacement also breaks the `tabindex=-1` focus target and any `aria-describedby` reference. (`EXPERIENCE.md § Accessibility Floor → Headings`, A20; record UX-DR2.3, D4.) *Fix:* one of: (a) the *same* `<h1 id="headline" tabindex="-1">` element always exists in the result region; idle text "oddspark" is visually hidden (`.sr-only`), settle sets `textContent` — say "same node, textContent changes"; or (b) the masthead wordmark is the permanent `h1` and the Spark title is `h2` with section labels `h3` (heading nav still works; avoids an invisible heading and the swap). (a) is more faithful to the record; either is AA. Also require `document.title` to change on settle (already done in JS; state it, and server-render it for `/s/:id` and the no-JS POST).
- **[medium]** `notice` non-visual perceivability. As a bare `<p>` before the `h1`, an SR reads it as unlabelled body text before the heading; the three draft strings are self-explanatory, so it is *perceivable*, but its "notice, not error" status is carried only by colour (panel + entropy bar) — 1.4.1 Use of Color is satisfied only because the text itself states the situation. (`EXPERIENCE.md § notice`; `DESIGN.md § notice`.) *Fix:* give it `role="note"` (announced as "note" by NVDA/JAWS/VoiceOver, no live behaviour, no dismiss semantics) and require the string to name the cause in words (all three drafts do — lock that as a rule for future strings). Do **not** use `role="alert"`/`status` on it. In the no-JS/permalink case it is static content, which is correct.
- **[medium]** `/how` has four Mermaid diagrams, not one, loaded from a third-party CDN (`cdn.jsdelivr.net`, L2361) — contradicting "no third-party script" in `EXPERIENCE.md § Foundation` and CSP/privacy claims. Accessibility specifics: (1) with JS off, `<pre class="mermaid">` shows raw Mermaid source and SRs read it; (2) Mermaid's rendered SVG contains real `<text>` nodes, so even with `accTitle`/`accDescr` the diagram is read twice (SVG text + your list); (3) diagram borders use `#3D4750` (1.95:1) — fails 1.4.11 for the graphic's meaningful boundaries; (4) `.mermaid{min-width:520px}` inside `overflow-x:auto` — acceptable under the 1.4.10 two-dimensional-image exception, but the scroll container needs `tabindex="0"` + an accessible name to be keyboard-scrollable. (`EXPERIENCE.md § /how`; record UX-DR2.12, D16.) *Fix:* wrap each rendered diagram in `<figure aria-hidden="true">` (the ordered list is the accessible equivalent) or `role="img" aria-label="…"` if the SVG text is not to be exposed; hide the `<pre>` source until rendered (`visibility:hidden` on `.mermaid:not([data-processed])`); set `actorBorder`/`primaryBorderColor` to ≥3:1 (`#67737F` passes at 4.02:1); or pre-render server-side to remove the CDN. Correct "one diagram" to "four".
- **[medium]** `copy link` target size and state announcement. `.copy` is an unpadded 11px inline-styled `<button>` (~17.6px tall). It squeaks past 2.5.8 only via the spacing exception (22px column gap, 8px row gap → 24px circles do not intersect), which breaks the moment the footer wraps differently or `json` sits closer. Its "copied" text swap is not announced. (`DESIGN.md § footer-link`; `EXPERIENCE.md § Accessibility Floor → Keyboard`.) *Fix:* give `.copy` (and the footer links) `padding: 4px 0` / `min-height: 24px`, and announce "Link copied" via the same `role="status"` element used for loading. Chips are non-interactive — 2.5.8 does not apply; say so.
- **[medium]** Focus-ring contrast is stated against "its background" but the entropy ring is drawn *outside* the control (offset 2–3px) so its adjacent colour is void (5.82:1 — pass). Against the button fill it is 1.0–1.76:1. As worded, a dev who sets `outline-offset:0` or `box-shadow` inset would silently fail. (`DESIGN.md § components.*.focusRing`; record UX-DR2.5.) *Fix:* word it as "2px `{colors.entropy}` outline with ≥2px offset so the ring sits on `{colors.void}`; never inset."
- **[low]** `disabled` opacity 0.45 puts label/fill at 1.9–2.5:1 — exempt under 1.4.3 (inactive control) but the *label text* is still the only progress affordance; consider keeping label at full opacity and dimming only the fill.
- **[low]** `{colors.solar-m}` `#E06A3F` is byte-identical to `{colors.error}`; on an M-class day the primary button, the wordmark half and the invalid-input border are the same colour, undermining "solar never signals error". Cognitive, not a WCAG failure. *Fix:* nudge `error` (e.g. `#E8734B`, still >5:1) or accept and note.
- **[low]** Placeholder `example.com` uses browser default grey (~4.0:1 on panel) — placeholder is not the label so not a failure, but set it explicitly to `{colors.dim-raised}` for consistency.
- **[low]** `history.pushState('/s/<id>')` on settle should be suppressed for domain/downgrade Briefs (no permalink exists) — otherwise back/refresh yields the 404 page from a state the visitor did not choose. Not a WCAG criterion; a predictability issue (3.2.x spirit).
- **[low]** `EXPERIENCE.md` says the canvas is "removed from the tab order" — a `<canvas>` is not focusable by default; the sentence will make a dev add `tabindex="-1"`, which is harmless. `aria-hidden="true"` is correct and there is no focus trap. Legend uses `<u>`/`<b>`/`<em>` for colour — fine, but `<u>` should be a `<span>`.
- **[low]** 10.5px minimum text is not a WCAG failure but is below most agency floors (12px); at 400% zoom it is legible. 1.4.12 text-spacing: `letter-spacing` overrides on tracked labels are fine because they are not `!important` and nowrap is being removed.

## Recommended manual checks (what axe will not catch here)

1. **Settle announcement, one SR + one browser (VoiceOver/Safari, NVDA/Firefox):** press Strike from the keyboard; confirm you hear exactly one "Working…" sentence, then exactly one title announcement, notice text once, and that the card is *not* read end-to-end unprompted. Repeat for a downgrade Brief and a house Brief.
2. **Focus continuity through `disabled`:** Tab to Strike, press Enter, wait; on success confirm focus is on the `h1` (screen shows the ring only if `:focus-visible` matches — verify with a keyboard press) and on 502 confirm focus is on the button, not `<body>`. Then Tab once and confirm the next stop is the first link inside the card / invitation, not the top of the document.
3. **400 path:** type `not a url`, submit, confirm focus lands in the input, the SR reads the field name + "invalid" + the API message (via `aria-describedby`), and that fixing the value and resubmitting clears `aria-invalid` and the message.
4. **Five accent classes:** force `--solar` to each of A/B/C/M/X (query param or env stub) and screenshot the button, the provenance hot values, the `?` glyph and the wordmark; measure the button label pair with a contrast picker. Axe checks only the served class of the day.
5. **No-JS full path:** disable JS, submit the form empty and with a domain; confirm an HTML page (not JSON) comes back with the Spark title as `<title>` and `h1`, and that a bad URL returns the shell with the message next to the field. Refresh after a domain POST and confirm behaviour matches the spec.
6. **Motion:** with reduced-motion *off*, confirm a visible control pauses the canvas rotation and dot; with it *on*, confirm no rAF is running (Performance panel) and the scramble is skipped.
7. **Zoom/reflow:** at 320px CSS width (400% on 1280) and 200%: no horizontal scroll on `/` (chips wrap, input ≤100%, provenance hashes break), footer links remain ≥24px targets or keep 24px spacing, focus rings not clipped by `overflow`; on `/how` the diagram scroller is keyboard-focusable and the ordered list is present without JS.
8. **Permalink & 404 page:** open `/s/:id` with JS off — h1/title/content present; open an expired id — focus at document start reads the `h1` product name and then the "no longer available" line, and Strike works.
9. **`copy link`:** keyboard-activate it, confirm a status announcement ("Link copied") and that the target is ≥24px or spacing-compliant after the footer wraps at 320px.
